Lesson 0007 · Jenkins from zero

Make and Diagnose a Red Build

You have a green baseline. Now create one safe failure on purpose so you can practice reading the first useful error instead of fearing red builds.

The One Thing

A shell command communicates success or failure with its exit status. Jenkins documents that an sh script which exits with a nonzero status normally fails the step. That makes sh 'exit 1' a perfect controlled red-build exercise.

Sources: Pipeline sh step reference and Using a Jenkinsfile: Build.

Temporary Change

Change only the Test stage. This deliberately fails after printing a helpful message.

stage('Test') {
    steps {
        sh 'echo About to fail on purpose'
        sh 'exit 1'
    }
}

Restore Change

After you have inspected the red build, restore the placeholder so your baseline becomes green again.

stage('Test') {
    steps {
        sh 'echo No tests configured yet'
    }
}

The Exercise Loop

Edit Jenkinsfile and replace the Test stage with the controlled failure.
Commit and push the change to GitHub.
Run the Jenkins Pipeline job again.
Open the failed build's Console Output.
Find the Test stage boundary.
Find + exit 1 and the line explaining the failed exit code.
Restore the original Test stage, commit, push, and run again.
Confirm the final build returns to Finished: SUCCESS.

Expected Red-Build Clues

The exact formatting can vary, but the useful clues should look like this:

[Pipeline] { (Test)
[Pipeline] sh
+ echo About to fail on purpose
About to fail on purpose
[Pipeline] sh
+ exit 1
script returned exit code 1
Finished: FAILURE

The diagnosis is: the Test stage failed because the shell command exit 1 returned a nonzero status.

Clue Reader

Pick a clue and learn what it tells you.

The failing run was inside the Test stage when this part of the log appeared.

Practice

1. What normally happens when sh 'exit 1' runs?

2. Which line is the most useful cause clue?

3. How do you prove the failure was controlled?

Your Takeaway

A red build is a signal. Your job is to locate the stage, identify the command, read the exit/error message, and make one focused fix. A controlled exit 1 failure gives you that muscle memory without risking a real project.
