Lesson 0009 · Jenkins from zero

Replace a Placeholder with a Smoke Test

Your pipeline has moved past “can Jenkins run?” The next win is making the Test stage prove one small real thing about this repository.

The One Thing

A smoke test is a small, fast check that proves the build is basically wired correctly. Jenkins’ Jenkinsfile docs describe the Test stage as the place where automated tests run, and the sh step fails when a command exits nonzero. That means simple shell checks can become real CI signals.

Sources: Using a Jenkinsfile: Test and Pipeline sh step reference.

Before

This was a placeholder. It always passed as long as Jenkins could print text.

stage('Test') {
    steps {
        sh 'echo No tests configured yet'
    }
}

After

The pipeline now checks that the expected repository shape exists after checkout.

stage('Test') {
    steps {
        sh 'test -f Jenkinsfile'
        sh 'test -d lessons'
        sh 'test -d reference'
    }
}

What Each Check Proves

test -f JenkinsfileThe CI entry point exists as a file.
test -d lessonsThe lesson archive exists as a directory.
test -d referenceThe reference archive exists as a directory.

Why This Is a Better Beginner Test

echo answers: “Can Jenkins print text?”

test -f and test -d answer: “Did Jenkins check out the repository shape I expect?”

If someone renames Jenkinsfile or removes lessons, the command exits nonzero, Jenkins marks the step failed, and the console output gives you a useful cause.

Command Reader

Practice

1. Why is test -f Jenkinsfile more useful than echo?

2. What does test -d lessons prove?

3. What happens if one of these test commands returns nonzero?

Your Takeaway

You now have a real, tiny Test stage. It is not application testing yet, but it is CI behavior: check an expectation, pass when true, fail when false, and make the console output useful.
