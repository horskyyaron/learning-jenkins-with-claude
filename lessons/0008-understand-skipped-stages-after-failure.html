Understand Skipped Stages After Failure

You asked the right operational question: if a stage fails, what happens next? This lesson teaches the default failure path and the one exception worth knowing now.

The One Thing

In a normal Declarative Pipeline, a failed step stops the current flow of work. A failing sh command normally fails the step; remaining normal steps in that stage are skipped; later normal stages are skipped; the build finishes as FAILURE.

Sources: Pipeline sh step reference and Pipeline post syntax.

The Default Failure Chain

1. Step failssh 'exit 1' returns nonzero.
2. Stage failsThe stage containing that step turns red.
3. Later work skipsLater normal steps and stages do not run.
4. Build failsThe run ends with Finished: FAILURE.

Your Current Example

Your current Jenkinsfile has the failure in Inspect. That means Test should be skipped.

stage('Inspect') {
    steps {
        sh 'pwd'
        sh 'exit 1'
    }
}

stage('Test') {
    steps {
        sh 'echo No tests configured yet'
    }
}

What You Should See

The exact wording varies by Jenkins version and plugins, but the meaning should be clear: Inspect failed, and Test did not run.

The Beginner Exception: post

Skipped normal stages are not the same as cleanup/reporting logic. Jenkins Declarative Pipeline has a post section for steps that run after a stage or Pipeline completes. The official syntax docs list conditions such as always, failure, and success.

pipeline {
    agent any
    stages {
        stage('Test') {
            steps {
                sh 'exit 1'
            }
        }
    }
    post {
        always {
            echo 'This runs after the Pipeline finishes'
        }
        failure {
            echo 'This runs only when the Pipeline failed'
        }
    }
}

You do not need post yet for your basic pipeline. Just know it exists so the rule is precise: later normal stages skip, but explicitly configured post-actions can still run.

Your Takeaway

The default Jenkins failure flow is protective: once normal work fails, Jenkins stops the remaining normal path and reports failure. That prevents a broken build from continuing into later stages as if everything were fine.
