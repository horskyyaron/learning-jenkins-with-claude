Lesson 0010 · Jenkins from zero

Add a Build Stage That Produces Output

Your smoke-test Pipeline is green. The next win is adding a real Build stage, even though this repository is a learning workspace rather than an app.

The One Thing

A useful Build stage should create or assemble something. Jenkins’ Jenkinsfile docs describe the build stage as where source code is assembled, compiled, or packaged, and note that the Jenkinsfile is the glue that invokes the actual build tool. For this learning repo, the build output is a tiny generated file: build/summary.txt.

Sources: Using a Jenkinsfile: Build and Pipeline sh step reference.

The New Shape

InspectShow where Jenkins is and what files were checked out.
BuildCreate a generated output in build/summary.txt.
TestVerify repository shape and generated build output.

Build Stage

stage('Build') {
    steps {
        sh 'mkdir -p build'
        sh 'printf "Jenkins learning workspace\n" > build/summary.txt'
        sh 'ls build'
    }
}

Test Addition

The Test stage now checks the output from Build. This connects stages: Build creates something, Test verifies it exists.

sh 'test -f build/summary.txt'

Expected Console Story

[Pipeline] sh
+ mkdir -p build
[Pipeline] sh

[Pipeline] { (Test)

Finished: SUCCESS

The important evidence is summary.txt appearing in the Build stage and test -f build/summary.txt passing in the Test stage.

Your Takeaway

The pipeline now has a basic CI shape: inspect the workspace, build an output, then test expectations. This is still tiny, but it maps directly to real software projects where Build might run npm run build, mvn package, or make.

The next lesson should save the generated build output with archiveArtifacts so Jenkins keeps something from the run.
