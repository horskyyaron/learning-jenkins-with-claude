Make Jenkins Run a Real Command

Lesson 1 taught you the shape of a Pipeline. This lesson teaches the first useful CI skill: putting terminal commands inside Jenkins with the sh step.

The One Thing

The sh step runs a shell command on the Jenkins agent. If the command exits with a non-zero status, Jenkins treats that step as failed and the Pipeline normally stops.

Sources: Jenkins documents sh as a Pipeline step used to execute shell commands in the Pipeline documentation and shows it in real Jenkinsfile examples in Using a Jenkinsfile.

echo vs sh

echo 'Testing...'

A Jenkins Pipeline step that prints a message. Useful for clarity, but it does not run your project tests.

sh 'npm test'

A Jenkins Pipeline step that asks the agent's shell to run an actual command. This is how CI does real work.

The CI Translation

For a beginner CI pipeline, translate what a developer does locally into stages:

Inspect: Where am I? What files are here?

Build: Can the project compile or package?

Test: Do the automated tests pass?

Jenkins is not replacing your build tool. The Jenkinsfile is the glue that calls tools like npm, Maven, Gradle, Make, or pytest.

Read This Jenkinsfile

This is still safe and generic. It proves Jenkins can run shell commands before you connect a real app.

pipeline {
    agent any

    stages {
        stage('Inspect') {
            steps {
                sh 'pwd'
                sh 'ls'
            }
        }

        stage('Test') {
            steps {
                sh 'echo No tests configured yet'
            }
        }
    }
}

Failure Is the Signal

CI is valuable because it can say “stop, this change broke something.” A shell command communicates success or failure with an exit status. In Unix-like shells, 0 means success and non-zero means failure. Jenkins uses that signal to mark the step and Pipeline result.

sh 'exit 0'  // success
sh 'exit 1'  // failure

Your Takeaway

A useful CI Pipeline is mostly a clear sequence of stages that run real commands. sh is the bridge from Jenkins to your project tools.
