Write Your First Jenkinsfile

You can now read a Pipeline and understand sh. The next win is creating the file Jenkins looks for: a real Jenkinsfile at the root of a repository.

The One Thing

A Jenkinsfile is the Pipeline definition stored in source control with the project. This is called Pipeline-as-code: the CI process can be reviewed, versioned, and changed alongside the application code.

Sources: Jenkins Pipeline documentation and Using a Jenkinsfile.

What Changed

This workspace now has a real file named Jenkinsfile at the repository root. That matters because Jenkins can be configured to read that file from source control and run the Pipeline it defines.

Why Root?

By convention, Jenkins looks for a file named Jenkinsfile in the repository root when you define a Pipeline from source control. Keeping it there makes the CI entry point obvious to humans and tools.

The file is not magic by itself. Jenkins still needs a job configured to read the repository. But the repository now contains the pipeline definition.

Your Starter Jenkinsfile

This file is intentionally small. It proves the agent can see the workspace and run a placeholder test stage.

pipeline {
    agent any

    stages {
        stage('Inspect') {
            steps {
                sh 'pwd'
                sh 'ls'
            }
        }

        stage('Test') {
            steps {
                sh 'echo No tests configured yet'
            }
        }
    }
}

How to Think About This File

agent any asks Jenkins to pick an available agent to run the work.
stage('Inspect') answers: “What workspace did Jenkins give me, and what files are visible?”
stage('Test') is a placeholder for the command that will eventually prove the project still works.
