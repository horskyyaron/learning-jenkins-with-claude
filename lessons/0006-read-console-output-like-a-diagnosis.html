Lesson 0006 · Jenkins from zero

Read Console Output Like a Diagnosis

You ran your first SCM Pipeline successfully. The next win is learning a repeatable reading pattern so console output becomes evidence, not noise.

The One Thing

Console Output is the detailed log for one Pipeline run. Jenkins' getting-started guide sends you to build #1 and Console Output to see the full run output after clicking Build Now. Read it in order: trigger, checkout, stage output, final result.

Sources: Getting started with Pipeline and Running Pipelines.

The Four-Pass Scan

1. TriggerWhy did this run start?
2. CheckoutDid Jenkins fetch the right repo, branch, and commit?
3. StagesWhich stages and shell commands ran?
4. ResultDid it finish with success, failure, or unstable?

What Your Run Proved

Your pwd command proved Jenkins had a workspace for this job. Your ls command proved Jenkins checked out files from Git and could see the repository contents, including Jenkinsfile.

stage('Inspect') {
    steps {
        sh 'pwd'
        sh 'ls'
    }
}

What It Did Not Prove Yet

The run did not prove the project builds or has real tests. Your current Test stage only echoes a message, so it is a placeholder. That is fine: first you prove Jenkins can run the repository, then you replace placeholders with real project commands.

Healthy Beginner Output

A successful run should contain stage boundaries, shell steps, command output, and a final success result.

[Pipeline] stage
[Pipeline] { (Inspect)
[Pipeline] sh
+ pwd
/var/jenkins_home/workspace/learning-jenkins
[Pipeline] sh
+ ls
Jenkinsfile
lessons
reference
[Pipeline] }
[Pipeline] stage
[Pipeline] { (Test)
[Pipeline] sh
+ echo No tests configured yet
No tests configured yet
[Pipeline] }
Finished: SUCCESS

Line Reader

Pick a line type and learn what signal it gives you.

A stage boundary. This tells you Jenkins entered the named stage from the Jenkinsfile.

Practice

1. What does [Pipeline] { (Inspect) tell you?

2. What does the output of pwd show?

3. If the run ends with Finished: FAILURE, what should you do first?

Your Takeaway

A successful beginner console output proves four things: the job started, SCM checkout happened, the expected stages ran, and Jenkins finished successfully. When failure comes later, this same reading loop tells you where to look first.

The next lesson should replace the placeholder Test stage with a deliberately failing command so you can practice diagnosing a real red build safely.

Ask the agent follow-up questions if anything is unclear. Good questions: “What does checkout scm mean?” or “How do I tell which command failed?”
